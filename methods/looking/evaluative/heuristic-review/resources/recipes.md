# Heuristic Review: Recipes

How Heuristic Review combines with other methods. Positioning confirmed in the practitioner teaching session.

---

## What it is (so the agent knows when to reach for it)

Heuristic Review is **one of several complementary evaluative methods**: Heuristic Review, Think-Aloud Testing, Critique, System Usability Scale. They aren't ranked; each evaluates for a different reason. Reach for Heuristic Review when:
- A team has something new and wants to evaluate it against the rules of good design before sharing it with people
- A team wants to make an existing system better and measure the improvement
- A team doesn't have access to users

The practitioner's stance: *the most important thing is that you evaluate your designs.* Ideally, combine methods.

---

## Recipe: Review, Then Test

```
Rough & Ready Prototyping → build something concrete
    ↓
Heuristic Review → score it, fix the obvious issues
    ↓
Think-Aloud Testing → real people, real tasks
    ↓
Iterate, and re-score
```

A Think-Aloud Test after a Heuristic Review is likely to be more productive: the known issues are gone, so participants' time goes on what only they can reveal, which often doesn't trace back to any heuristic.

---

## Recipe: Improve an Existing System and Measure It

```
Heuristic Review → baseline score (e.g. 4 / 20) and findings
    ↓
Severity + prioritize → fixes ordered by effect on the system
    ↓
Fix
    ↓
Heuristic Review again → re-score to measure the improvement
```

Where users are available, add Think-Aloud Testing or the System Usability Scale alongside, to evaluate from their side too.

---

## Recipe: Author Project Design Principles

```
Alternative Worlds → study analogous systems, harvest their best practices   (not yet in this library)
    ↓
Author 4–6 heuristics → evaluative principles for this project (not values)
    ↓
Test them on a real example → refine
    ↓
Heuristic Review against them → throughout the project
```

Alternative Worlds is one source. Principles can also come out of research synthesis, a shared definition of success, or a published set adapted to the project.

---

## Recipe: With Critique

Heuristic Review evaluates against named principles; Critique gathers open, structured feedback. Run both when you want coverage of principle violations *and* of concerns no heuristic names (strategy, fit, ambition). Critique reviewers can include users and customers as well as internal people.

---

## Coaching Note

If a team hasn't evaluated their design at all, any evaluative method is the first move, and Heuristic Review is often the fastest to start because it doesn't need users. If a team has only run a Heuristic Review and has access to the people they're designing for, ask what watching some of them use it would add. Frame it as complementary, not as the method they skipped.
