# Think-Aloud Testing — Resources

This folder contains supplementary materials for the Think-Aloud Testing method, organized by type. Resources grow over time as practitioners use the method and contribute examples, templates, and organizational variations.

---

## What's Here

| File / Folder | What it contains |
|---|---|
| `tips.md` | Practitioner wisdom, facilitation gotchas, and the things that trip people up |
| `faq.md` | Questions that come up repeatedly — grows over time |
| `ai-usage.md` | How to use Think-Aloud Testing with AI tools, and an honest account of why this is one of the least simulatable methods |
| `recipes.md` | How Think-Aloud Testing connects to and sequences with other methods |
| `references.md` | External reading, videos, related frameworks, and further resources |
| `visuals/` | Sketch-planations, the in-session and unmoderated diagrams, the Time/Love Continuum |
| `templates/` | The moderated test protocol and the unmoderated participant brief |
| `examples/` | Real sessions: an unmoderated transcript and a full worked synthesis pipeline |

**Already covered elsewhere:**
- Overview and full method reference → `../method.md`
- Facilitation cheat sheet → `../mechanics.md`
- Teaching arc content → `../teaching.md`

## How to Use These Resources by Mode

| Mode | What to reach for first |
|---|---|
| **Teaching** | `examples/` for the worked story → `visuals/` for the in-session and Time/Love diagrams → `references.md` for further reading → `../teaching.md` for the arc |
| **Facilitating** | `templates/` for the protocol and brief → `../mechanics.md` for the cheat sheet → `tips.md` for in-the-moment guidance |
| **Coaching** | `tips.md` for situational advice → `recipes.md` for method sequencing → `faq.md` for common questions → `references.md` for further reading |
| **Executing** | `ai-usage.md` for what AI can and cannot do here — especially the synthesis role and the limits of simulation |

## Provenance

This method was built via Pathway A — taught directly by a practitioner (David Townson, What Could Be) who has run and taught it many times, with real templates and a real worked example. Files marked `source: canonical` contain core WCB methodology content. Files marked `source: custom` are organizational additions contributed by a specific team or context. Both are valid; the distinction helps future practitioners understand what is general and what is specific to one context.
